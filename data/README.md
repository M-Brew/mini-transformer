
# Dataset

This directory stores the text corpus and its processed representation.

## Structure

- `raw/`: Text corpus (`corpus.txt`) and cached source downloads (`gutenberg/`).
- `processed/`: Token IDs and tokenizer metadata generated by the preparation script.

## Preparing the data

The corpus is Jane Austen's six novels. See [DATASET.md](DATASET.md) for its
source, license and preparation procedure. Build it, then tokenize it:

```bash
python scripts/build_corpus.py --config configs/baseline.yaml
python scripts/prepare_data.py --config configs/baseline.yaml
```

Any other UTF-8 corpus can be placed at `data/raw/corpus.txt` instead.

## Generated files

- `train.pt`: Training token IDs.
- `validation.pt`: Validation token IDs.
- `tokenizer.json`: Character vocabulary and tokenizer metadata.
- `metadata.json`: Dataset preparation metadata.

## Tokenization

The initial implementation uses a character-level tokenizer.

The tokenizer is fitted on the training partition only. Characters not encountered in training are mapped to the reserved `<unk>` token.

## Splitting

If the corpus contains document separators (U+001E), whole documents are
assigned to training or validation, with validation documents spaced evenly
through the corpus. Otherwise the raw text is split into contiguous training
and validation partitions. Either way, the split happens before tokenization
and window construction.

The validation partition is not used for model parameter updates.

## Reproducibility

`build_corpus.py` records the source, license, preparation details and hashes in `corpus_manifest.json`. `prepare_data.py` records the corpus hash in `processed/metadata.json`.

Do not commit large datasets without checking their license and repository size.
